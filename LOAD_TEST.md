## How it got here

The first run of this script measured p95 = 404 ms at 349 req/s. Profiling found three causes, then a fourth change followed:

1. The board handler built its zod query schema on every request. It is now built once at startup.
2. `MONGODB_URI` used `localhost`. Node tries IPv6 first and mongod was listening on IPv4 only, so each new pooled
   connection waited about 250 ms. The URI now uses `127.0.0.1`.
3. Board pages are cached as serialized JSON, shared by concurrent readers of the same page, and cleared on every team change.
4. A cached page is answered before logging, helmet, the rate limiter and the body parsers run (the "fast path"). Those cost
   more CPU than the response itself, which matters most on a small instance.

An earlier uncached run measured 346 ms p95 at 420 req/s, against about 80 ms at 1,500 req/s here. Several changes landed
in between (the zod fix, the URI fix, later middleware changes) and I did not isolate which accounts for how much, and
machine load varies run to run. Treat single runs as indicative, and compare the two columns within one run.
